# 巡检与服务器直传

在「机器 → 管理巡检组」保存巡检组。表格每台机器一行，勾选两台 SSH 主机后显示链路诊断。组内记录常用机器、关注路径和明确确认的共享挂载。切换组后会记住选择。容量趋势随页面可见时的采样累积，显示最近十分钟内最多 60 个点。余量低于或等于 10% 时标记，挂载超时与端点离线显示时间和状态。组内已经移除的端点由 MCP 在 `missing` 返回。

NFS 候选使用挂载来源、实际服务地址、端点身份和本机路由作为本次确认边界。变动后需要重新确认。当两台机器的挂载快照都足够新，且源路径和目标路径在同一已确认挂载中的相对位置完全一致时，转交原路径引用。同一文件的重复复制或移动会结束在准备阶段。

## 服务器直传

在链路诊断选两台 SSH 主机及各自私网地址，测通后点「允许此机器对直传」。会话按两端配置身份生效。可随时从同一入口停用。允许后，Linux SSH 普通文件剩余至少 8 MiB 时优先使用直传，目标暂存需要在本机文件系统。小文件、Windows 和不满足条件的路径沿用现有 SSH／原生复制。

VS Code 宿主通过已登记的两条 SSH 连接建立只服务当前任务的 TLS 通道。目标助手锁定暂存文件后才发出监听回执。证书指纹经已有 SSH 控制连接确认。发送方验证指纹后提交一次性凭证，数据直接进目标暂存。每次目标落盘后才更新可恢复偏移。SSH 丢失时沿现有任务流程检查暂存锁和已确认前缀，然后恢复；已知安全停止的直传可回到 SSH 中转继续。完整校验和目标提交之后才执行移动所需的源删除。

「更多 → 文件传输 → 性能详情」展示直传、中转、目标落盘及校验。秒数分开显示执行墙钟时间和各端测量值。直传失败的切换原因留在任务详情，目录交互继续走独立控制通道。

## Agent

- `map_patrolGroups` 查询当前地图的巡检组，再用 `map_systemResources({groupId})` 取精简快照。
- `map_transfer({...,transport:"relay"})` 可指定本次只走兼容路径。默认按用户对机器对的设置选择。
- 侧边栏「诊断与接入 → 绑定此窗口」显示窗口地图与 Codex 目标。确认后更新对应启动参数。旧地图离线时 MCP 给出原因与可选窗口，当前运行中的客户端仍可用 `map_bind` 显式切换。
